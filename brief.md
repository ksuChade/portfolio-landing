## 1. Цель и аудитория

### Цель сайта

**Главная:** Превратить незнакомца в клиента — от «зашёл» до «оставил заявку» — без холодных продаж. Сайт работает как автономный продавец 24/7.

**Вторичные:**
- Отсеять нецелевых клиентов (неподходящие задачи)
- Сформировать доверие до первого контакта
- Задокументировать экспертность (кейсы, процесс)

### Целевая аудитория

**Первичная (платит деньги):**
- Эксперты, которые продают товары или услуги
- Владельцы малого и среднего бизнеса, 25–55 лет
- Нетехнари: не знают что такое React, но примерно знают что хотят
- Устали от ненадёжных исполнителей и «пропавших» фрилансеров
- Бюджет: от 20 000 ₽ до 150 000 ₽ на проект
- Боль: время уходит на ручные процессы, сайт не приводит клиентов, нет подходящего инструмента, дорого и долго, каждая правка стоит денег  

### Ключевые вопросы, на которые отвечает сайт

1. «Это про меня?» — hero
2. «Можно ли доверять?» — trust bar + testimonials
3. «Он понимает мою задачу?» — problem mirror + services
4. «Он делал такое раньше?» — portfolio / cases
5. «Как это будет работать?» — process
6. «Что мне сделать прямо сейчас?» — CTA
7. Соберу прототип, который можно потыкать и попробовать до покупки

## 2. Структура страницы

Гибридная архитектура: главная (one-page с якорями) + отдельные страницы кейсов и услуг.

```
index.html              ← главный лендинг (one-page)
services.html           ← страница услуг с ценами
cases/
  ├── case-1.html       ← детальный кейс #1
  ├── case-2.html       ← детальный кейс #2
  └── case-3.html       ← детальный кейс #3
```

## 3. Контент по секциям

### Header / Nav

**Структура:**
- Слева: логотип или имя (текст, 18px, Space Grotesk Medium)
- Центр: якорные ссылки — Услуги · Работы · Процесс · Обо мне
- Справа: кнопка «Обсудить проект» (primary, small)

**Поведение:**
- Прозрачный при загрузке, белый с тенью при скролле вниз (sticky)
- На мобиле: бургер → drawer меню с теми же ссылками
- Активный пункт подсвечивается при скролле через секцию

### Секция 1 — Hero

**Задача:** За 3 секунды ответить «Я попал туда, куда нужно?»

**Макет:** две колонки на desktop — текст слева, фото справа. На мобиле: фото сверху (круглое), текст снизу.

**Контент:**

```
[BADGE]  Доступен для новых проектов · Июнь 2026
```

```
[H1 — главный заголовок, ~60px]
Создаю сайты, приложения
и AI-агентов — под ключ.
```

```
[H2 — subheadline, ~20px, muted]
Работаю с предпринимателями и командами:
от идеи до запущенного продукта.
Фиксированная цена, понятный процесс, живой результат.
```

```
[CTA PRIMARY]  Обсудить проект →
[CTA SECONDARY]  Смотреть работы ↓
```

**Фото:**
- Профессиональное фото, нейтральный фон
- Размер: 420×520px на desktop, круг 200px на мобиле
- Лёгкая тень: `box-shadow: 0 20px 60px rgba(99,102,241,0.15)`

**Дополнительно:**
- Под фото — три micro-stats в ряд:
  ```
  [N] проектов    [N] лет опыта    [N]★ средняя оценка
  ```

**Технические требования:**
- `<h1>` — единственный на странице
- `alt` у фото: «[Имя] — разработчик сайтов, приложений и AI-агентов»
- Badge доступности: CSS-анимированная зелёная точка + текст


**Технические требования:**
- Логотипы: SVG монохром (grayscale: 0.7, opacity: 0.6)

- На мобиле: горизонтальный скролл или 2 ряда

### Секция 6 — Process

**Задача:** Убрать страх «чёрного ящика». Клиент видит: знаю что будет, когда плачу, что получаю.

**Контент:**

```
[LABEL]  Как проходит работа

[H2]
От первого сообщения
до запущенного продукта
```

**5 шагов (горизонтально на desktop, вертикально на мобиле):**

```
[01]  Разбор задачи
      Бесплатный звонок 30–40 минут.
      Рассказываете задачу — я задаю вопросы.
      Что делаете вы: просто говорите.
      Срок: 1–2 дня

[02]  Предложение и смета
      Фиксирую объём, стек, сроки и цену.
      Никаких «посмотрим по ходу» —
      всё прописано до начала.
      Что делаете вы: согласовываете и подписываете.
      Срок: 2–3 дня

[03]  Разработка итерациями
      Работаю короткими спринтами (1–2 недели).
      После каждого — показываю результат.
      Что делаете вы: смотрите, даёте обратную связь.
      Срок: по договору

[04]  Приёмка и запуск
      Тестирование, правки, деплой.
      Показываю как пользоваться,
      передаю все доступы и документацию.
      Что делаете вы: принимаете работу.
      Срок: 3–5 дней

[05]  Поддержка
      30 дней бесплатной поддержки после запуска.
      Отвечаю в течение 2 часов в рабочее время.
      Что делаете вы: работаете с продуктом.
```

**Под шагами:**
```
[CTA]  Начать с бесплатного звонка →
```

### Секция 9 — FAQ

**Задача:** Закрыть оставшиеся возражения до CTA. Клиент должен выйти из FAQ готовым к контакту.

**Контент (7 вопросов, accordion):**

```
Q: Сколько стоят ваши услуги?
A: Стартовая цена зависит от задачи: лендинг — от 80 000 ₽,
   веб-приложение — от 200 000 ₽, AI-агент — от 60 000 ₽.
   Полные тайеры — на странице услуг. Я всегда фиксирую цену
   до начала работ — никаких сюрпризов по ходу.

Q: Сколько времени занимает разработка?
A: Лендинг — 1–2 недели. Веб-приложение (MVP) — 4–8 недель.
   AI-агент — 1–3 недели. Точные сроки фиксируются в договоре.

Q: Что если мне не понравится результат?
A: После каждого спринта вы видите промежуточный результат
   и даёте обратную связь. Правки входят в стоимость.
   Глобально менять направление в середине — не входит,
   но это и прописывается в брифе заранее.

Q: Смогу ли я сам вносить изменения в сайт после запуска?
A: Да. Передаю все доступы + инструкцию по самостоятельному
   редактированию. По запросу — видеоурок для вашей команды.

Q: Вы работаете один или у вас команда?
A: Работаю один — это значит, вы всегда общаетесь с тем,
   кто непосредственно делает продукт. Никаких менеджеров
   как прослойки, никаких «уточню у разработчика».

Q: Работаете ли вы по договору?
A: Да, всегда. Договор фиксирует объём, сроки, цену
   и условия правок. Принимаю оплату как физлицо
   (чек самозанятого) или по счёту для юрлиц.

Q: Что происходит после запуска?
A: 30 дней бесплатной поддержки: отвечаю на вопросы,
   фиксирую баги. Дальше — опциональный ретейнер
   на поддержку и развитие.
```

**Технические требования:**
- Accordion: открывается по клику, остальные закрываются
- Анимация: плавное раскрытие (CSS transition, max-height)
- `<details>` / `<summary>` — семантически правильно

## 4. Дизайн-система

### Стиль и настроение

**Стиль:** Minimal Monochrome + Indigo Pop  
**Настроение:** Спокойная уверенность. Не кричит, не продаёт агрессивно. Говорит тихо — но точно. Как умный специалист на переговорах.

**Ключевые прилагательные:** чистый · структурированный · профессиональный · современный · человечный

## 6. Анимации и интерактив

### Принципы

- **Анимации дополняют, не отвлекают.** Если убрать — контент не теряет смысл.
- **Скорость:** 150–300ms для микро-интерактивов, 400–600ms для входа секций.
- **Easing:** `ease-out` для входа элементов, `ease-in-out` для переходов.
- **`prefers-reduced-motion: reduce` — отключает всё.** Обязательно.

---

### Scroll-triggered анимации (Vanilla JS + CSS)

**Что анимируется при входе в viewport:**
- Секции: fade-in + translateY(24px → 0)
- Карточки: staggered вход (задержка 100ms между карточками)
- Числа в Trust Bar: count-up анимация
- FAQ аккордеон: плавное раскрытие

**Реализация через IntersectionObserver:**

```js
const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      entry.target.classList.add('visible');
      observer.unobserve(entry.target);
    }
  });
}, { threshold: 0.1 });

document.querySelectorAll('.animate-on-scroll')
  .forEach(el => observer.observe(el));
```

```css
.animate-on-scroll {
  opacity: 0;
  transform: translateY(24px);
  transition: opacity 0.5s ease-out, transform 0.5s ease-out;
}
.animate-on-scroll.visible {
  opacity: 1;
  transform: translateY(0);
}
/* Stagger для карточек */
.card:nth-child(2) { transition-delay: 0.1s; }
.card:nth-child(3) { transition-delay: 0.2s; }
```

### Активный пункт навигации при скролле

```js
const sections = document.querySelectorAll('section[id]');
const navLinks = document.querySelectorAll('nav a[href^="#"]');

const navObserver = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      navLinks.forEach(link => link.classList.remove('active'));
      const activeLink = document.querySelector(
        `nav a[href="#${entry.target.id}"]`
      );
      if (activeLink) activeLink.classList.add('active');
    }
  });
}, { rootMargin: '-40% 0px -60% 0px' });

sections.forEach(s => navObserver.observe(s));
```
